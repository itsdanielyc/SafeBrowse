# Safepay and SafeBrowse: documented security comparison

Reviewed 3 September 2026 against current public documentation and the SafeBrowse working tree. This is a source review, not a penetration test of either product. Bitdefender statements below are vendor claims unless explicitly identified as historical engineering explanations. SafeBrowse implementation evidence establishes what the code requests, not resistance to every attack.

**Assessment:** SafeBrowse implements several useful parts of a dedicated browsing environment, but the available evidence does not support security parity with Safepay. The largest documented gaps are product-level malware and fraudulent-site defenses, integration with a VPN and banking detection, and an established application update/support process. Similar appearance, a separate desktop, or a shared Chromium ancestry does not establish equivalent protection.

| Area | What Bitdefender documents | SafeBrowse evidence and practical difference |
| --- | --- | --- |
| Desktop isolation | Safepay provides desktop isolation and runs independently of ordinary browsers. [Safepay guide](https://www.bitdefender.co.uk/consumer/support/answer/89049/) | Normal mode creates a fresh UUID-named Win32 desktop and authenticates its worker through inherited handles before opening a browser. Its host still runs as the same Windows user with inherited desktop access controls; it is not a VM or a separate security principal. See `DesktopManager::create_safe_desktop` in [manager.rs](../../src/desktop/manager.rs), [launch_auth.rs](../../src/desktop/launch_auth.rs), and [SECURITY.md](../../SECURITY.md). |
| Screen capture | Bitdefender claims that Safepay prevents malware screenshots. [Safepay guide](https://www.bitdefender.co.uk/consumer/support/answer/89049/) | [capture.rs](../../src/security/capture.rs) requests and verifies `WDA_EXCLUDEFROMCAPTURE`; recording requires an explicit launch flag and warning. Microsoft limits display affinity to supported capture mechanisms and says it is not a strict content-protection guarantee. This is not evidence of equivalent malware resistance. [Microsoft API boundary](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setwindowdisplayaffinity) |
| Keystroke interception | Bitdefender claims protection from keyloggers and supplies a virtual keyboard. [Safepay guide](https://www.bitdefender.co.uk/consumer/support/answer/89049/) | SafeBrowse's keyboard changes document fields through [input.js](../../src/keyboard/input.js), avoiding simulated OS keystrokes. The receiving page can still observe its own fields and events. Neither that mechanism nor a separate desktop proves protection from mouse observation, browser compromise, or privileged malware. [Documented limits](../../SECURITY.md) |
| Malicious sites and endpoint threats | Safepay claims fraudulent-site detection and web filtering, and is included in Bitdefender's Windows security products rather than distributed separately. [Safepay guide](https://www.bitdefender.co.uk/consumer/support/answer/89049/) | SafeBrowse explicitly enables and reads back WebView2's SmartScreen requirement before website or popup navigation. Windows policy can override that setting. SafeBrowse has no project-operated reputation service, malware scanner, or endpoint-protection integration. See [the shared WebView policy](../../src/browser/security.rs), [SECURITY.md](../../SECURITY.md), and [Microsoft's setting contract](https://learn.microsoft.com/en-us/dotnet/api/microsoft.web.webview2.core.corewebview2settings.isreputationcheckingrequired). |
| Browser sandbox | The current consumer guide describes a protected browsing environment but does not specify its current process-token, AppContainer, site-isolation, or sandbox policy. [Safepay guide](https://www.bitdefender.co.uk/consumer/support/answer/89049/) | SafeBrowse preserves WebView2's default sandbox/isolation settings and refuses elevated or high-integrity host tokens before startup. The host is not itself sandboxed, and exploit containment has not been independently demonstrated. Engine names alone do not establish a stronger boundary. See [integrity.rs](../../src/security/integrity.rs), [config.rs](../../src/config.rs), and [SECURITY.md](../../SECURITY.md). |
| Network protection | Safepay documents VPN functionality for unsecured Wi-Fi. [Safepay guide](https://www.bitdefender.co.uk/consumer/support/answer/89049/) | SafeBrowse has no VPN client or tunnel enforcement. Ordinary HTTPS and any separately installed VPN remain distinct controls. A VPN does not by itself establish website legitimacy or protect a compromised endpoint. |
| Banking detection | Bitdefender documents banking-site detection in other Windows browsers, prompts to use Safepay, and an optional automatic handoff for saved sites. It also acknowledges missed detections. [Automatic launch troubleshooting](https://www.bitdefender.com/consumer/support/answer/1435/) | SafeBrowse has manual navigation, bookmarks and a launch URL. It does not monitor other browsers or automatically transfer banking sessions. This is primarily a workflow and adoption difference, not proof of stronger browser containment. |
| Updates and integration | Bitdefender documents hourly automatic update checks, staged product rollouts and occasional restart requirements. Its current release notes include a Safepay/SecurePass fix. These are product update statements, not a promise that every Chromium patch reaches Safepay within an hour. [Windows product updates](https://www.bitdefender.com/consumer/support/answer/32196/) | Microsoft services the installed WebView2 Evergreen Runtime; SafeBrowse must restart to use a newly installed runtime. This does not update SafeBrowse's own Rust/JavaScript code. The reviewed project has no application updater, and its security policy identifies distribution/update review as release work. [README](../../README.md), [SECURITY.md](../../SECURITY.md), [Microsoft distribution documentation](https://learn.microsoft.com/en-us/microsoft-edge/webview2/concepts/distribution) |

## Historical engineering evidence and its limits

In the archived **Bitdefender 2013** forum, Cristian Amarie identifies himself as Safepay's lead developer. He describes a separate desktop in the same logon session, virtual-keyboard input delivered internally rather than as keyboard messages, interception of Print Screen shortcuts, storage protected by the product's shield service, and cloud URL checks. He also explicitly recognizes the severity of kernel compromise and explains that Safepay complements the antivirus. These are first-hand historical statements, useful for understanding the design lineage; they are not a verified description of the current binary or a current guarantee. Other commenters' claims that Safepay runs outside the operating system are not supported by the developer's explanation. [Archived engineering discussion](https://community.bitdefender.com/en/discussion/37584/2nd-try-safepay-keyloggers-and-screenscrapers/p1)

CEF supports Chromium's sandbox but requires correct platform integration; current Windows documentation describes a sandbox bootstrap or an application built within the CEF/Chromium toolchain. The existence of CEF support does not prove Safepay's exact configuration, and replacing WebView2 with CEF would not supply Bitdefender's other product protections. [CEF sandbox requirements](https://chromiumembedded.github.io/cef/sandbox_setup.html)

## Evidence needed before claiming parity

- Define concrete attackers and test both products against the same permitted capture, input-observation and same-user process-access cases. A disabled recording flag or a successful functional test is not a security verdict.
- Verify effective native sandbox/process restrictions, profile/settings access controls, trusted-UI boundaries, runtime versions and patch delivery. Public product descriptions do not establish these details.
- Treat fraudulent-site filtering, endpoint malware defenses, VPN behavior and application updates as separate capabilities with their own tests. No independent security certification or Safepay-specific comparative test was established in this review.

Implementation validation is recorded separately in [VALIDATION.md](../VALIDATION.md).
